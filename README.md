# Захищений TLS-клієнт і сервер

Консольний клієнт і сервер для локального обміну текстом або невеликим UTF-8 файлом через TLS. Сервер перевіряє облікові дані, приймає дані тільки після входу, звіряє SHA-256 і пише події у JSONL.

## Структура

- `server.py` — TLS-сервер, JSON фреймування, авторизація, журналювання.
- `client.py` — клієнт із перевіркою довіри та імені сертифіката.
- `generate_cert.py` — створення RSA-3072 сертифіката з SAN localhost.
- `add_user.py` — створення облікового запису з прихованим введенням пароля.
- `analyze_logs.py` — звіт Markdown за JSONL журналом.
- `security_checks.py` — перевірка відхилення недовіреного сертифіката й hostname.
- `tests/` — автоматичні перевірки pytest з реальним локальним TLS-з'єднанням.
- `data/`, `logs/` — локальні дані, виключені з Git.

## Вимоги та встановлення (Windows 11)

Потрібен Python 3.13 із PATH. У CMD з каталогу проєкту:

```cmd
py -3.13 -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## Сертифікат і обліковий запис

```cmd
python generate_cert.py
python add_user.py alice
```

Введіть пароль двічі у прихованому запиті. Мінімальна довжина — 12 символів. Самопідписаний `data\server.crt` є довіреним коренем саме для локального запуску клієнта; приватний `data\server.key` не передавайте та не додавайте до Git.

## Запуск

Відкрийте два окремі вікна CMD у каталозі проєкту. У першому:

```cmd
.venv\Scripts\activate
python server.py
```

У другому:

```cmd
.venv\Scripts\activate
python client.py --user alice --message "Вітаю, захищений сервер"
```

Клієнт запитає пароль. Сертифікат перевіряється системним TLS стеком із `data\server.crt` та hostname `localhost`; вимкнення перевірок не використовується. Для передачі невеликого текстового UTF-8 файлу:

```cmd
python client.py --user alice --file notes.txt
```

## Протокол і безпека

Кожне повідомлення — JSON UTF-8 із чотирибайтовим мережевим префіксом довжини. Межа повідомлення — 1 MiB, таймаут читання/запису — 30 секунд. TLS мінімум 1.2. У сесії після п'яти послідовних невдалих спроб сервер закриває з'єднання. Для коректного повідомлення сервер повертає SHA-256 і кількість байтів; пошкоджений digest відхиляється. Для тексту файла вміст декодується як UTF-8.

## Перевірки

```cmd
python -m pytest -q
python security_checks.py
python analyze_logs.py
```

Звіт записується в `logs\analysis.md`. Тести охоплюють позитивний TLS-вхід/передачу, недовірений сертифікат, неправильний hostname, невідомого користувача, неправильні паролі, доступ до входу, контроль SHA-256 та аналіз подій. TLS-помилки до завершення handshake можуть бути видимі тільки мережевому стеку; JSONL фіксує помилки, які застосунок може спостерігати після прийняття з'єднання.

## Приклади подій

Журнал містить timestamp UTC, назву події, IP, ідентифікатор користувача за наявності, статус, код відповіді, TLS версію, cipher, розмір і безпечну причину помилки. Паролі, ключі й повний вміст повідомлень не журналюються. Журнали та локальна база облікових записів не призначені для публікації.
